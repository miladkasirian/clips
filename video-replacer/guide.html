Course Video Replacer

You record a lecture in whatever language you teach in. It comes back as the same video with an American English voice, still in step with the picture, with subtitles in both languages. The picture is never re-encoded and the video never leaves your computer.

This page assumes nothing. If you are sitting at a computer that has never seen this program, start at the top and do not skip.

What this is

One folder, and one program inside it. You double-click Course Video Replacer.exe, choose your .mp4, and press Start. Four files come back:

week 3 lecture.mp4  what you recorded
  → week 3 lecture.en.mp4   the same video, your voice replaced
  → week 3 lecture.original.srt subtitles in the language you spoke
  → week 3 lecture.english.srt  subtitles in English
  → week 3 lecture.report.txt   every line that had to be squeezed

The three things worth knowing before anything else Your video never leaves this computer, unless you deliberately choose the YouTube route. Otherwise only a small audio file is sent, and only to OpenAI.
Nothing is spoken until you say so. A panel shows you every line first.
An hour of lecture costs under two dollars, and there are two ways to make that less.

1 · Put the project on GitHub

Skip this if the folder is already somewhere you can copy from. This is for the case where the project lives on one computer and you want it on another without a USB stick — and it is also a backup, which the folder on one machine is not.

Before you push anything, check what is being ignored The folder contains your API key and your Google sign-in. .gitignore already keeps key.txt, client_secret.json, youtube_token.json, the voice, work, output and input folders, the .venv and every .exe and .mp4 out of the repository. Open it and read it once with your own eyes before the first push. A key pushed to GitHub is a key you have to throw away, even from a private repository.

On the computer that has the folder

  1. Install Git for Windows if it is not there. Accept every default.
  2. On github.com/new, make a repository. Name it something like video-replacer. Private is the right choice unless you want strangers reading it. Do not tick "Add a README".
  3. Open a terminal in the project folder — in File Explorer, type cmd into the address bar and press Enter — and run these one at a time:
git init
git add .
git status

Stop at git status and read the list. If you see key.txt, client_secret.json, youtube_token.json or anything from voice/ in it, do not continue — the .gitignore is not being picked up. Fix that first.

git commit -m "Course Video Replacer"
git branch -M main
git remote add origin https://github.com/YOUR-NAME/video-replacer.git
git push -u origin main

Git will ask you to sign in to GitHub the first time and remember it afterwards.

2 · Get it onto the new machine

Either way works. The result is one folder.

From GitHub

git clone https://github.com/YOUR-NAME/video-replacer.git

What you get is the code, not the built program — .exe files are deliberately kept out of the repository. Two choices:

  • Copy the exe across separately (email it to yourself, or a USB stick). It is one file, about 12 MB, and it needs nothing installed to run.
  • Or build it, if the new machine has Python: double-click build-exe.bat. It prepares what it needs the first time and writes Course Video Replacer.exe beside itself. See Changing the code.

By copying the folder

Copy the whole folder. Leave out .venv, _build, work and output — they are large and they rebuild themselves. Do bring glossary.txt and the voice folder if you have cloned voices, because those are yours and nothing can recreate them.

What must NOT travel with it key.txt, client_secret.json and youtube_token.json hold credentials. Moving them is not dangerous in itself — it is your own machine — but it is cleaner to paste the key in again on the new computer and press Sign in again. If you do copy them, never put them anywhere shared.

3 · ffmpeg

ffmpeg does all the work on the video itself: pulling the sound out, changing the speed of a line, and putting the new audio back. It is not optional and it is not something you have to go and find.

Open the app, go to Settings. Beside ffmpeg it says either installed or missing — press Get it. If it says missing, press Get it. The app downloads about 30 MB, unpacks it into an ffmpeg folder beside itself, and says so in the log on the Convert tab. Nothing is installed system-wide and nothing else on the computer changes.

If ffmpeg is already on the machine If you installed it before, through winget or by putting it on the PATH, the app finds it and leaves it alone. It looks in three places: the PATH, its own ffmpeg\bin folder, and winget's package folder — that last one because winget only adds itself to the PATH of shells opened afterwards, which is a trap worth knowing about.

4 · The OpenAI key

This is the one thing that costs money, so it is worth understanding rather than just pasting.

Getting one

  1. Go to platform.openai.com and sign in. This is the API platform, not chatgpt.com. They are different products on the same account.
  2. Open Billing and add a payment method, then add credit — $5 or $10 is plenty to start, and it does not expire quickly. A ChatGPT Plus subscription does not pay for API calls. If you skip this step every run fails with a quota error, and the error will not say "you have no money", it will say something less obvious.
  3. Open API keys → Create new secret key. Copy it. You are shown it once and never again; if you lose it, delete it and make another.
  4. In the app: Settings → Your OpenAI key, paste it into the box, press Save.

The key is written to key.txt beside the app, on your computer. It is sent to nobody but OpenAI, and it is in .gitignore, so it does not go into the repository. The box hides it; the show tick beside it reveals it if you need to check you pasted the whole thing.

The one mistake everybody makes Copying the key with a space or a line break on the end. The app trims what it can, but if a run fails immediately with an authentication error, tick show and look at what is actually in the box.

A spending limit is worth five minutes

On the platform site, under Limits, you can set a monthly budget and an email alert. Nothing here can run away with your money — the costs are small and every run is something you started — but a key that leaks is somebody else's key until you notice, and a hard limit turns that from a bill into an inconvenience.

Your first conversion

  1. The video. Press Choose… and pick your .mp4. The first time, it opens in the input folder beside the app; after that it opens wherever you were last. Nothing about the picture is re-encoded, so a 500 MB file is no slower to handle than a small one.
  2. The language you speak in the video. Leave it on Work it out from the audio. It nearly always gets this right on its own. More on languages.
  3. Where the results go. Defaults to the output folder beside the app. Change it to anywhere you like; it will be remembered.
  4. How much a line may be sped up to fit. Leave it at 120%. Why this exists.
  5. Show me every line first. Leave this ticked, at least until you trust it. What the panel does.
  6. Remember these settings — ticked by default. Everything on every tab is written to config.json when you press Start, so the app opens tomorrow the way you left it today.
  7. Press Start. The log fills in underneath: six steps, each one saying what it is doing.

Partway through it stops and the review panel opens. Nothing has been spoken and nothing has been spent on the voice at that point.

The panel before it speaks

This exists because of one specific failure. Say you invented a variable called MLAD and you pronounce it out loud in Persian. The transcriber writes ملاد, and the translator, reasonably, turns that into "Milad" — in every line, in every video. A name it has never heard has no correct translation and it will not know it is wrong.

So it stops here. Fix anything wrong in the English box and press Approve and make the video. What you type is exactly what gets spoken.

On the cardWhat it means
001The line number, so the report can point at it.
00:12 – 00:18The moment of video this line covers. The English will be spoken across exactly that.
(about 16 words fit here)How many words that moment holds at a natural speaking pace. The translator was told this number. If you rewrite a line much longer than its budget, it will have to be sped up or run over.
The right-aligned lineWhat you actually said, as it was heard.
The box below itThe English that will be spoken. Editable. Emptying it keeps the previous text rather than making the line silent.
Cancel really does mean cancel Pressing Cancel stops the run and empties the work folder. A half-finished transcript of a private lecture is not something to leave lying around on disk. The same happens if you simply close the app.
If you would rather it did not stop Untick Show me every line first on the Convert tab. It then goes straight through. Worth doing once you have a glossary that covers your usual vocabulary — and not before.

What comes out

FileWhat it is
name.en.mp4 Your video with the English audio. The picture is the identical stream that went in — copied, not re-encoded, so there is no generation loss and the mux takes seconds even on a 500 MB file.
name.original.srt What you actually said, in the language you said it, with real timings. Read this once after a run in a language you have not used before.

name.report.txt Every line that did not fit comfortably, and which ones were the real cause. How to read it.

Reading the report

The report separates two things that look the same in the finished video and are not:

Lines whose English is too long for their moment: 1
Lines merely pushed along, or sped up a little:    1

Shorten these and run it again if they matter:
  00:00:30,000  line 4  too long for its 4.5s: needs 8.7s of speech
     And finally we arrive at the answer, which is the number we ...

  00:00:34,500  line 5  sped up to 114% to fit

Line 4 is the culprit. Its English genuinely needs 8.7 seconds and it has 4.5. Line 5 is a victim — it only had to hurry because line 4 spilled into it. An earlier version of this program listed both the same way, which sent you off fixing the wrong sentence.

The fix for a culprit is to say less in that moment, not to make the voice unlistenable. Shorten the English in the review panel next time, or record that part saying fewer words.

Any language in, English out

English always comes out. Almost anything can go in. The transcriber knows about a hundred languages — Persian, Hindi, Arabic, Urdu, Turkish, Spanish, Chinese and the rest — and it works out which one it is hearing from the audio itself. A lecture in Hindi is the same run as one in Persian: choose the file, press Start.

The language list sits below the video on the Convert tab — you can see it in the screenshot above. Common languages are named; any other ISO code — ja, ko, pt — can be typed straight into the box.

When naming the language actually helps Measured on a real Persian lecture, naming the language changed nothing — the transcript came back identical, because it had already worked the language out. It earns its place in one situation: a lecture that genuinely switches between two languages, where the guess can wander from one piece of audio to the next. Naming it settles the argument.

If you were already speaking English

It still works, and it is worth being clear about what it does: a rewrite, not a translation. Your own words are kept wherever they work; what goes is the false starts, the "um"s, the sentence you began twice, and anything that will not fit the moment of video it belongs to. Then the American voice you picked speaks it, in step with the picture, and your own voice is gone.

So an English lecture comes out tidier and in a different voice. If what you wanted was your own English recording left alone, this is not the tool for that.

One honest limit Everything measured on this page was measured on Persian, because that is what the lectures are. The same machinery applies to any language and there is no reason it would behave differently, but that is reasoning, not evidence. The first time you record in a new language, open .original.srt and read it — it is the transcript everything else is built on.

Words it would otherwise get wrong

Two different problems, one file, and it fixes both:

1. Names and terms the writer must not translate

The review panel is for the mistake that happened once. The glossary is for the one that would keep happening. ملاد = MLAD tells the writer that when it sees ملاد it must write MLAD, in every line of every video, for ever.

2. English words you say out loud inside another sentence

This turned out to be most of the errors in real lectures. You say "Add Voice" in the middle of a Persian sentence and the transcriber writes it back phonetically as اد ویس. It is not mishearing you; it is hearing you correctly and writing it in the wrong alphabet.

Both sides of every glossary line are handed to the transcriber before it listens. Knowing a word is coming is what lets it hear the word. Measured on one real minute:

What was triedWhat changed
whisper-1, as it wasthe baseline
+ told the language is Persiannothing at all — the two came back identical
+ given the glossary as a hintthe big one. "Add Voice" instead of اد ویس, "Output" instead of اد پود, تبدیل instead of تبلیل
gpt-4o-transcribe insteadnot better. Different mistakes, not fewer — and no timestamps, so it cannot be used here anyway

It costs nothing. Put every English term you say out loud into the glossary, on the day you first notice it.

3. What is left is fixed by reading, not by listening

By the time a mishearing reaches the transcript it is a spelling problem — ضب for ضبط, گذینه for گزینه — and something that reads the language can fix that without hearing the audio again. That is the Tidy up the transcript's spelling tick in Settings. It is told firmly not to invent: where a passage is genuinely unclear it is left alone, because an obviously wrong word is better than a confidently wrong sentence.

The eleven ready-made voices

onyx, ash, echo, ballad, verse, sage, alloy, fable, coral, nova, shimmer. They all cost exactly the same, so the only question is which one you want to listen to. The male ones are onyx, ash, echo and verse.

  • Hear it plays a sample of the selected voice, if one has been made.
  • Make all samples speaks the same short paragraph in all eleven and writes them into the samples folder, so you can compare them properly. It costs a few cents in total and you only ever do it once.

Adding a voice of your own

Add a voice… takes any recording of somebody speaking and makes a voice out of it. This is the biggest single change you can make to how the finished video sounds — and it runs on your own computer, so it costs nothing per run and nothing leaves.

What you give it

Any audio or video file ffmpeg can read: .m4a, .mp3, .wav, .mp4, .mov, .mkv, .aac, .ogg. A video file is fine — only the sound is used. Thirty seconds to a minute of clear speech, one person, no music, no second voice.

What actually happens to your file

It is never modified and never uploaded. A copy of it is made, and the copy is what the model gets:

  1. ffmpeg reads it and throws the video away if there is any.
  2. It is converted to mono, at 22 050 Hz — what the model expects. Stereo and a higher sample rate give it nothing.
  3. The silence at the start is trimmed off, because leading silence is not a voice and the model would try to copy it.
  4. It is capped at 40 seconds. Past about that the model gains nothing and only gets slower.
  5. The result is written as voice\YOUR-NAME.wav, and the name appears in the list immediately.

So a 40 MB .m4a becomes roughly a 1.7 MB .wav. That file is the voice; there is no model to train and nothing else stored. Delete the .wav and the voice is gone.

Give it a recording in the language it has to speak Give it English, not Persian. The model copies the timbre of whatever it is given, and handing it the language it has to produce gives it far more to work with. Compare _your-cloned-voice.mp3 with _cloned-from-persian.mp3 in the samples folder and the difference is not subtle.

The first time you use it

The model is XTTS-v2, and it has to be installed once: Settings → The local voice → Install. That is a few gigabytes, and it all goes into a .venv folder beside the app — nothing else on the computer is touched. The first time a cloned voice actually speaks, the model itself downloads (about 1.8 GB) and that run takes a few extra minutes. After that it is loaded once per run and kept warm.

Two things about the local voice It is licensed by its authors for non-commercial use — fine for your own teaching material, worth checking if that ever changes.
And it is a real voice clone. Do not make one of somebody who has not agreed to it.

Graphics card or processor

This only matters for a cloned voice. The eleven ready-made voices are spoken by OpenAI, not by your computer, and your hardware is irrelevant to them.

SpeedAn hour of lecture takes
NVIDIA graphics card0.7× real timeabout 40 minutes
Processor only2.3× real timeover two hours

Those are measured, not estimated. Without a card it still works — it installs the processor build, notices there is no card, and uses the processor. Nothing fails and nothing has to be configured. It is simply slower.

The trap that cost a whole afternoon On Windows, pip install torch gives you the processor build even on a machine with a perfectly good NVIDIA card, and nothing warns you. It installs, it imports, it runs — three times slower than it should, for ever, silently.

That is what the Use the graphics card tick in Settings is for: it installs from the CUDA index instead. Tick it before pressing Install. And the status line next to Install does not just say "installed" — it asks the installed library which device it will actually use and tells you, so a silent processor build cannot hide.

If the card runs out of memory partway through a run, the voice moves to the processor by itself, says so in the log, and carries on. It does not crash and it does not lose the run.

The YouTube route — why it exists

YouTube's own machine writes better Persian than anything reachable through an API. That is not a comfortable thing to write in the documentation of a program that transcribes Persian, but it is true, and it was measured rather than assumed.

So there is a second choice of who writes down what you said. It is in Settings → Who writes down what you said, and the default is unchanged — leave it alone and nothing on this page applies to you.

What actually happens when you choose YouTube

You still choose an mp4 and press Start, exactly as before. There is no link to paste and nothing to upload by hand. Behind the scenes:

  1. The video goes up to your own channel, as Unlisted. A resumable, chunked upload, so half a gigabyte that dies at 90% does not start again from nothing. The log counts it up in tenths.
  2. It waits for YouTube to write the captions, checking every twenty seconds and saying so, up to the limit you set in Settings (20 minutes by default).
  3. It reads the caption track. If there is more than one it prefers a published track over YouTube's automatic one. The log names the kind YouTube reported (standard or ASR) rather than guessing what it means — on your own fresh upload a track marked standard is still usually YouTube's work, not yours.
  4. It deletes the upload again. Whether or not the captions worked. That is in a finally, so a failure anywhere above it does not leave a lecture sitting on your channel.
The one risk, stated plainly YouTube locks videos uploaded through an API project it has not audited as private, and that cannot be appealed. Because the video is deleted within minutes of going up, nothing should remain either way — but this is your channel, and uploading through an unaudited project is a thing YouTube would rather you did not do. If that matters to you, leave the setting on Whisper. If it does not, this is the cheaper and better transcript.
If the deletion itself ever fails The log says so, in capitals, with the video id, and tells you to remove it yourself. A lecture quietly left on a channel is the one outcome that must never happen silently, so it is the one thing here that shouts.

Setting it up, from zero

Every step is in a browser except the last two. It reads longer than it takes.

In the Google Cloud console

  1. Make a project. console.cloud.google.com → the project dropdown at the top → New project. Name it anything.
  2. Turn on the API. APIs & Services → Library, search for YouTube Data API v3, open it, press Enable.
  3. Fill in the branding. Google Auth Platform → Branding. It wants an app name and your email. It also wants, and will not let you past without, a home page and a privacy policy link — both public URLs on a domain you own, and both listed under Authorized domains. A GitHub Pages site works: https://you.github.io/something/ and a privacy.html beside it. Leave the terms-of-service box empty; it is not required.
  4. Add the scope. Data Access → Add or remove scopes. Type force-ssl in the filter, tick https://www.googleapis.com/auth/youtube.force-ssl, press Update, then Save. If the filter finds nothing, the API from step 2 is not enabled on this project. That one scope covers all three things the app does: upload, read the captions, delete.
  5. Publish it. Audience → Publishing status → Publish app. Do not skip this. An app left on Testing expires your sign-in every seven days. In production it keeps working. You do not need to be verified — unverified in production just means a warning screen the first time and a cap of 100 users, and you are one of them. Ignore the Verification Center entirely.
  6. Make the client. Clients → Create client. Application type: Desktop app. Create, then Download JSON.
The email matters All of this has to be done on the Google account that owns the YouTube channel. Sign in later with a different account and the upload goes to the wrong channel, or is refused.

In the app

  1. Settings → Your YouTube sign-in → Choose client_secret.json… and pick the file you downloaded. The app copies it into place itself, under the right name. Nothing to rename or move.
  2. Press Sign in. A browser opens once. Sign in with the account that owns the channel. Google warns you the app is unverified — that is your own app: Advanced → Go to (unsafe).
  3. The status beside the buttons should read signed in. It never asks again.
  4. Settings → Who writes down what you said → YouTube.

Two files now live beside the app: client_secret.json and youtube_token.json. Both are gitignored. Delete the token to sign out, or revoke it at your Google account permissions page.

Using it, and what to expect

Choose the mp4. Press Start. That is all — the Convert tab looks exactly the same as it does with Whisper, because from where you sit nothing has changed.

It will take longer. A 500 MB lecture is a real upload, and then YouTube writes the captions when it gets round to it — usually a couple of minutes, sometimes not. The log says what it is waiting for rather than looking hung, and if the wait runs past the limit in Settings it gives up, deletes the upload, and lets Whisper write the transcript instead. You do not lose the run.

Fitting English to your picture

English is never the same length as the sentence it came from. That is the hard problem here, and it is solved in four stages, in this order:

  1. Say it at a natural speed. If it fits, done.
  2. Speed it up — never past the limit on the Convert tab (120% by default). The filter used changes speed without changing pitch, so a hurried line still sounds like the same person rather than a chipmunk.
  3. Borrow the silence that follows it. If you paused after that sentence, the English may run into the pause.
  4. Let it run over, and name it in the report. Better an honest overrun you can see than a voice sped up to 200%.

Why sentences, and not fragments

This is the change that mattered most, so it is worth understanding.

The transcriber hands back short pieces, not sentences. A real two-minute lecture came back as 37 of them, some two seconds long. Two seconds holds about five spoken words. So "When I select Spin here, the videos start playing" could not possibly fit, however it was written — while "And there," sat next door with two seconds and nothing to do. Neither could lend room to the other while they were separate lines.

Joining fragments that are less than a breath apart into whole sentences, and telling the writer how many words each moment allows, took that same lecture from 23 lines that would not fit to none.

The two settings behind it longest_line (10 seconds) is how long a joined sentence may get. join_gap (0.8 seconds) is the pause that counts as a real break rather than a breath. They are on the Settings tab under "Rarely worth changing", and the name is accurate.

When something goes wrong

What you seeWhat it is
It fails immediately with an authentication error The key. Tick show in Settings and look at what is actually in the box — usually a stray space or half a paste.
A quota or billing error No credit on the OpenAI API account. ChatGPT Plus does not pay for this.
ffmpeg missing, right after installing it winget only adds itself to the PATH of shells opened afterwards. The app looks in winget's folder too, so press Get it and let the app have its own copy.
"That video has no captions yet" YouTube has not finished writing them. Wait a few minutes.

You have to sign in to YouTube again every week The app is still on Testing in the Google console. Audience → Publish app.

A run died half way and you do not want to pay twice Tick Keep the working files in Settings and run it again. It reuses the transcript and the English it already has.

The tests

python test-pipeline.py — 32 checks on a made-up 40-second lecture, with the three paid steps replaced by fakes. Nothing is sent anywhere and nothing is spent.

It does not check that the code runs. It measures the energy in the finished audio, half a second at a time, and asserts that each line's speech lands on the moment of video it belongs to and that the gaps between them stayed silent. It also checks that the picture came through as the same stream, that both subtitle files line up, that a line too long for its slot is capped and correctly blamed, that a hand-edit in the review panel is what actually gets spoken, that cancelling and closing both clear the work folder, that the language you pick reaches the transcriber, that YouTube's subtitles become lines with real timings, and that a refusal from YouTube falls back instead of stopping.

The last three open the real window and check that every setting survives a restart and that no tick or radio goes pale under the pointer. They skip themselves on a machine with no display.

Changing the code

You never need this to use the program. It is here for when you change something.

build-exe.bat

Double-click it. The first time, it makes its own small Python environment and installs PyInstaller into it. Then it bundles app.pyw and replacer.py into Course Video Replacer.exe, with the icon, and nothing else on the computer is touched. It needs Python installed; a normal user does not.

A trap worth knowing Run from a shell with a stripped PATH, PyInstaller could not resolve Tcl/Tk's DLLs and silently produced a 9.9 MB exe instead of about 11.9 MB — leaving out the window toolkit's data files. It launched. It looked fine. It misbehaved. If your built exe is not around 12 MB, it is not a complete build. Run the batch file from Explorer rather than from an unusual shell.
